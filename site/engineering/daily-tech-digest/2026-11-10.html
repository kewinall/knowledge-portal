Barracuda：新增實際利用警示，先收緊管理介面

威脅更新：2026-11-09原公告：11/2 · 驗證條件更正：11/5

加拿大 Cyber Centre 11/9 更新 AV26-1112，引述公開來源指出 CVE-2026-116606 已遭實際利用。本次新進展是威脅狀態，不是新漏洞或新修補。

影響範圍

此授權繞過漏洞影響 Email Security Gateway（ESG）。不需登入，但攻擊者必須能連到 Admin UI；若與 CVE-2026-111560 命令注入串連，可能取得 root 權限。

命令注入另影響 ADC、BMA、WCC、WAF、WSG，不能把這些產品都寫成具相同免驗證攻擊條件。

實務建議

先確認是否有受影響設備、管理介面可由何處存取，再核對最新韌體與安全修補是否都已套用。限制 Admin UI 只供可信任內網存取；未自動套用者依供應商程序補齊。

若發現可疑存取，依既有事件應變流程保留證據並調查。修補完成不等於證明先前未遭入侵。

核對修補，不只看單一版本

供應商列 ESG 修補為 BNSF-40425（原文分組 9.4.017+）或 BNSF-40430（<9.4.017）；加拿大公告則列 ESG <9.4.0.030。兩者標示方式不同，應依設備對照官方修補表，必要時向供應商確認，不自行改寫版本字串。

AWS Nitro Sandboxes：把 Agent 工作負載隔離到輕量 VM

發布：2026-11-09 · 已可用商用 AWS Regions · 須支援機型

AWS 新增以 Nitro Hypervisor 管理的輕量 VM，讓 EKS pod、ECS task 或自管 EC2 工作負載各自取得硬體隔離邊界，適合評估執行 LLM 生成程式碼與多租戶工作。

新能力與門檻

提供 cryptographic attestation，可依工作負載完整性驗證控制秘密釋出。並非所有 EC2 機型都適用：須核對 Nitro Enclaves 相容機型。

EKS 使用前須核對當前支援版本與升級窗口。AWS 表示功能本身無額外費用，EC2 與其他服務費用仍需計入。

實務影響與建議

先用一個可拋棄的 Agent 測試工作負載，比較既有容器與沙箱的啟動時間、記憶體成本、吞吐與故障復原。

驗證 IAM、網路出口、儲存掛載與監控。硬體隔離不能取代最小權限、輸入驗證及資料外傳管制，也不代表現有程式可零測試搬移。

採用界線

先確認 cluster 版本、instance type、AMI／runtime 與 Region，再設小規模試點。公告中的效能與資源利用敘述是供應商主張，本期未進行效能實測。

EKS Auto Mode／Karpenter：GPU 與 EFA 可依需求動態配置

發布：2026-11-09Auto Mode：Kubernetes 1.36+

AWS 宣布 EKS Auto Mode 與 Karpenter 支援 NVIDIA GPU、EFA 的 Dynamic Resource Allocation（DRA）。可用 ResourceClaim／ResourceClaimTemplate 描述裝置條件，搭配需求擴展 EC2。

對 AI 平台的影響

可表達 GPU 屬性、分享及 GPU／EFA 拓樸需求，較單純申請裝置數量更細緻。Auto Mode 內建 NVIDIA 與 EFA DRA drivers。

公告涵蓋除 AWS GovCloud（US）及 China 外的 Regions。自管 Karpenter 仍要另外核對 Kubernetes、feature gates 與 driver 支援矩陣，不能理解為所有組合都可直接使用。

實務建議

建立獨立測試 node pool，驗證 claim 分配／釋放、GPU sharing、EFA 拓樸、擴縮與失敗回復，再與既有 device plugin 工作負載比較。

避免同裝置被 DRA 與 device plugin 重複分配。公告中的同裝置類型隔離防護屬於 Auto Mode，不應直接套用到自管 Karpenter。

導入前的驗收

固定測試模型、batch size 及節點條件，量測排程等待時間、吞吐、利用率與成本。先保留回到原 node pool 的路徑，不把新功能公告當成正式環境已通過驗證。

Cloud Pathways 在 GKE 正式 GA；Slurm 仍是 Preview

11/9 新訊：Google Cloud 將多 slice TPU 的單一 Python client 協調能力正式提供於 GKE；支援 JAX 0.10.1+ 的版本化容器，範圍為提供 TPU v5e、v5p、v6e、7x 的相關 Regions。Cluster Director／Slurm 整合仍為 Preview。

建議：已有 JAX／多 TPU slice 工作負載才優先評估。固定容器與 JAX 版本，演練 slice 中斷、checkpoint 還原與資料載入，量測恢復時間及成本。一般 ETL 不必因此改架構。
