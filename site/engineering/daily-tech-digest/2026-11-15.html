Synology DSM：兩項遠端漏洞已提供修補版本

原廠初發：2026-11-10；更新：11-13 10:41（UTC+8）
台灣 TWCERT/CC 警訊：2026-11-13

Synology SA-26:19 列出 Auth API 的 SQL injection（CVE-2026-76954，CVSS 9.8）與 rsync 認證繞過（CVE-2026-85101，CVSS 8.6）。遠端攻擊者可能讀寫檔案或造成阻斷服務；官方已提供 DSM 各分支修正版，未列替代緩解措施。

一般實務影響

NAS 不只是檔案入口，也可能承載備份與服務資料。完整 build／Update 號比主版號更重要；這則公告不代表任何特定設備已遭入侵。

具體建議

核對型號、目前分支與完整版本，確認備份可還原後安排維護窗。依該機型支援路徑套用修補，重新讀回版本，並檢查分享、備份與必要套件；不要為了修補盲目跨大版。

02
值得試

AWS Batch on EKS：工作定義可指定更多安全邊界

AWS 發布：2026-11-13；適用：AWS Batch 的 Amazon EKS 工作定義

AWS Batch 新增 Linux capabilities、seccomp profile 及 Pod 層級 security context 設定，可讓工作在強制執行 Kubernetes Pod Security Standards restricted profile 的 EKS 環境中，以所需權限與系統呼叫執行。

一般實務影響

批次 ETL、模型處理等容器工作，可將權限需求放進工作定義，減少依賴寬鬆的叢集例外。這是設定能力擴充，不代表既有工作已自動符合 restricted 政策。

具體建議

先選測試工作，限制 capabilities、配置 seccomp，並確認檔案寫入與掛載權限。提交後讀回實際 Pod 規格，測正常及拒絕情境；若工作失敗，先調查所需系統呼叫與權限，不直接放寬為 privileged。

設定位置與採用界線

  • RegisterJobDefinition：容器的 securityContext 可設定 capabilities 與 seccompProfile。
  • podProperties.securityContext 可設定 Pod 共用值，例如 fsGroup；容器層級設定優先於 Pod 預設。
  • 可經 Console、CLI、SDK 或 CloudFormation 配置；官方宣布在提供 AWS Batch 的所有 AWS Regions 支援。
  • 公告未列 Kubernetes 最低小版本或 SDK 最低版本；實作前核對目前 API／IaC schema，不自行推定版本門檻。

持續觀察：既有映像、儲存驅動與權限需求是否相容。若沒有使用 Batch on EKS，無須僅為此功能遷移既有排程平台。

官方來源：AWS · Batch on EKS 安全設定
