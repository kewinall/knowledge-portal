P1 · 需檢查

Lima 2.3.0：Agent 沙箱的修補比新功能更先

版本：2.3.0 · 發布 2026-11-06CNCF 說明文：2026-11-08

CNCF 11/8 的新說明介紹 Lima 2.3，但版本與兩項安全公告實際於 11/6 發布。若用它隔離 AI Agent，應先確認 host 檔案與同步邊界，再評估新的平台功能。

變化與適用範圍

  • QEMU 檔案讀取邊界：Lima <2.3.0；當 guest 可寫入啟動 limactl 的工作目錄時，guest root 可能讀取掛載範圍以外、host 使用者可讀的檔案。2.3.0 已修補。
  • 同步審閱與套用之間的競態：≥2.1.0-alpha.0 且 <2.3.0 的 limactl shell --sync；guest 可在審閱後改動內容，使未審閱變更寫回 host。2.3.0 已修補。

實務影響與建議

先用 limactl --version 盤點版本，再核對 driver、掛載與同步設定。符合範圍者在測試環境驗證升級至 2.3.0，回歸檔案存取、同步差異與既有自動化。

未使用 Lima 或不符合該操作條件者，不需因此立即更換執行環境。VM 不等於所有 host 資料都已隔離。

風險邊界：兩項官方公告分別評為 Moderate、Low，均未列已知 CVE。同步問題仍需使用者接受同步；不是無互動的遠端攻擊。正式處置以資產與操作條件為準。

值得試：同步控制；實驗功能另行評估

2.3.0 新增 --sync-exclude 與 .limasyncignore，可用來排除不該同步的檔案。實務上可優先檢查 .git、.env 等敏感內容，並持續審閱實際差異；排除規則不能取代版本修補。

Windows HCS driver、Linux managed networks 與 limactl menu 仍為 experimental。先以可拋棄的測試 VM 驗證網路、掛載、權限及既有工作流相容性，不直接替換穩定環境。

ChatGPT 圖像生成錯誤已恢復

變化：OpenAI 11/8 官方事故通報顯示 Resolved，受影響項目為 ChatGPT 的 Image Generation。這不是已證實的整體 OpenAI API 中斷，也不是模型版本更新。

建議：若有失敗任務，先確認對話是否已有產出，再重試未完成部分，避免重複生成。沒有受影響的工作可暫不行動。

服務狀態是查核時的快照，個別帳戶體驗仍可能不同。官方顯示 11/8，但頁面未標示時間所屬時區，因此不換算精確台灣故障時段。
