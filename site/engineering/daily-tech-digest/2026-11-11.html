Exchange SE 11 月安全更新，別漏掉作業系統修復

發布：2026-11-10適用：Exchange SE RTM

Microsoft 發布 Exchange Server Subscription Edition（SE）安全更新。Exchange Online 已受保護，但環境內仍有 Exchange Server 或管理工具工作站者，仍需檢查更新。

實務影響

官方另指出，安裝 10 月 Windows Server 更新後的 Exchange 不穩定問題，應以 11 月 Windows Server 更新處理，不能把 Exchange SU 當作作業系統修復的替代品。

具體建議

先列出 Exchange、管理工具與 Windows Server 版本，按各自公告排維護窗口；更新後驗證收發信、OWA、佇列及服務健康。沒有自管 Exchange 者，不需為 Exchange Online 額外部署 SU。

驗證邊界

本期確認 SU 適用系列，不猜未核實的 CVE、嚴重度或 SU build。Windows Server 2022 的 11/10 更新為 KB5131090、OS Build 20348.5870；其他作業系統須查自己的更新頁，不可套用同一 KB。

正式更新前保留備份、回復方案及維護窗口；先跑健康檢查，再比對更新後版本與功能結果。

AgentCore Web Search API：不建 Gateway，也能取得搜尋結果

發布：2026-11-10 · GA介面：InvokeWebSearch

Amazon Bedrock AgentCore 新增直接搜尋 API，讓應用程式、自訂 Agent 迴圈及資料管線用 SDK／CLI 呼叫，不必為此建立 Gateway。這是 API 存取方式的新進展，不是首次推出網頁搜尋。

實務影響

結果包含排序與文字摘要，並在可取得時提供標題、URL 和發布時間；支援網域及發布時間篩選。可用於官方公告收集、知識更新候選與答案來源查證。

具體建議

以一組固定問題比較現有搜尋品質、延遲與成本；保留 URL、查詢時間及原始結果，缺發布時間就標缺漏。先限制可信來源，對搜尋文字維持不可信輸入處理。

成本與權限

公告價格為每 1,000 次查詢 US$7，沒有 Gateway 費用；不能因此推論整個 Agent 流程免費。呼叫使用 IAM，支援 PrivateLink 與 CloudTrail data events。所需權限為 bedrock-agentcore:InvokeWebSearch；部署前再核對 Region 支援、配額與所用 SDK 是否具備新介面。

本期不列未完整核實的 Region 清單或最低 SDK 版號。沒有外部新知需求、或現有搜尋已足夠者，可先觀察，不必遷移。

P2 · 值得試

CloudWatch PromQL 告警可銜接 EC2／Application Auto Scaling

發布：2026-11-10託管服務功能更新，無套件版號

CloudWatch 的 PromQL 告警新增自動擴縮動作支援，可讓 OpenTelemetry 指標延伸到容量控制，減少為擴縮另外維護傳統指標告警的需要。

重要限制

公告列出 simple／step scaling，並明確指出 PromQL 告警目前不支援 target tracking。查詢必須回傳單一序列，再與閾值比較；step scaling 依超出閾值的程度決定步階。

具體建議

先以通知模式檢查查詢是否穩定輸出單一序列，再於測試資源接擴縮。驗證缺資料、突波、回落與冷卻時間，設定最大容量與成本邊界，避免錯誤指標觸發反覆擴縮。

適用範圍與暫不行動原因

可透過 Console、PutMetricAlarm、CLI、SDK 或 CloudFormation 設定；適用於已有 CloudWatch PromQL alarms 的 Regions，採標準告警計價。EC2 與 Application Auto Scaling 各資源可用政策仍須按服務確認。

這不是 Kubernetes HPA 的直接替代，也不表示所有 Prometheus 序列都能直接拿來擴縮。既有 target tracking 表現穩定者，先觀察此限制，不必強改架構。
