01
有 1.31 就優先查 · Cloud

EKS 1.31 延伸支援到期：控制平面會分批升級

2026-11-26 · AWS 支援日曆 · 僅 EKS 1.31

11/26 是 EKS Kubernetes 1.31 延伸支援終止日。AWS 在到期後分批把既有控制平面升到最早仍受支援的版本，不保證個別叢集的升級時間。

一般實務影響

控制平面升版不等於節點一起升版。Managed Node Groups、自管節點和 add-ons 仍要對照版本與升級順序。

具體建議

有 1.31 就先確認當前控制平面版本與更新狀態，檢查 Upgrade Insights、已淘汰 API、CNI／CoreDNS／kube-proxy 與節點相容性，再安排節點更新和工作負載驗證。

驗證與限制

這是到期提醒，不是 1.31 的新版本。AWS 文件指出延伸支援結束後觸發的自動升級不可用原地回退功能。選擇測試叢集做部署、DNS、網路及排程驗證；無 1.31 叢集則不必處理。

官方來源：Amazon EKS · 版本生命週期與自動升級Amazon EKS · 升級流程

值得小規模試用 · Data Engineering

BigQuery 開放 Databricks／Spark SQL 轉譯預覽

2026-11-24 · BigQuery Migration Service · Preview

同一轉譯器可將 Databricks SQL 與 Apache Spark SQL 3.x、4.x 轉成 GoogleSQL，也支援從 Databricks 擷取 schema metadata。可從互動式樣本開始，再用批次轉譯盤點大批 SQL。

一般實務影響

適合快速辨識可轉譯的查詢與需人工改寫的區段。轉譯成功不代表資料、執行行為或查詢結果已等價。

具體建議

先挑聚合、join 和複雜日期運算各一批，在隔離環境比對筆數、主鍵、NULL、DECIMAL 精度、時區與 UDF 結果。通過才擴大試驗。

驗證與限制

把查詢和表／檢視表 DDL 分開匯出，必要時加入 schema metadata 供轉譯器判斷。轉譯與資料移轉是兩件事；結果不一致時應回到資料契約定位，不要以成功執行取代驗收。

Azure App Service for Linux：CVSS 10.0，Microsoft 標示客戶無須處置

MSRC 2026-11-19 · CVE 紀錄 11/24 UTC · TWCERT/CC 11/25

CVE-2026-109484 是 Azure App Service for Linux 平台層的權限提升漏洞。TWCERT/CC 於 11/25 整理公告；Microsoft 公告資料標示 Customer Action Required 為 No。

適用於 Microsoft 代管的 App Service for Linux 平台，不應直接套用到自管 Linux VM 或容器映像。10.0 是漏洞基本嚴重度，不等同客戶現在有待修的套件。

110.x／111.x 是此平台通報所用版本範圍，不是應用程式版本，也不能用映像 tag 推斷。台灣通報和 Microsoft 資料對處置的表達不同，客戶是否需要行動應以 Microsoft 對該服務及資源的指示判定。

短訊｜Claude API 後端換語言，如何確保行為一致？

Anthropic 於 11/25 公開 Python → Rust 的 Messages API 遷移做法。為了讓比較不被模型的非確定性干擾，他們只呼叫模型一次，把相同輸出重播給新服務，再比較兩邊的處理步驟。這是工程案例，不是新的 SDK 版本，也無須因此重寫客戶端。

重構 API 或 ETL 時可借用這個做法：新路徑先比對、不對外生效；涉及計費、通知或寫庫時，避免兩邊都做。先驗輸出與副作用一致，再逐步切流。
