01
優先修補 · Security

VMware VMSA-2026-0011：依產品與分支盤點修補

2026-11-24 初版 · Broadcom Critical · 最高 CVSS 9.8

Broadcom 公布新的 VMware 安全公告，涵蓋 ESX、vCenter、Workstation、Fusion、Tools 及 Avi Load Balancer。以官方對照表確認各產品與分支的受影響及修補版本。

一般實務影響

同一套虛擬化環境的管理面、主機和客體工具分別有更新條件。只更新 vCenter，不能推定 ESX、Tools 或其他元件也已修補。

具體建議

先收集 vCenter、ESX 與其他受影響元件的版本及 build，核對公告對照表。優先安排高風險的受影響元件，並在維護前確認備份、相容性及回復方案。

驗證與限制

原廠補充說明：已為上一份公告升至 vCenter 8.0 U3m 的環境，不需要為本公告再升同一元件；vCenter 9.1.x 及 ESX 仍需按本公告分別確認。更新後核對 build、主機連線和代表性 VM，不能只看下載或安裝紀錄。

官方來源：Broadcom · VMSA-2026-0011VMware · 更新與版本 FAQ
02
提早盤點 · Kubernetes

Kubernetes 1.38 預告：先查 CRI 與 kubectl 相容性

2026-11-23 官方預告 · 尚未發布；預計 2026-12-16

Kubernetes 1.38 規劃要求 container runtime 透過 CRI RuntimeConfig 回報 cgroup driver；舊式 kubelet 設定的 fallback 預設不啟用。kubectl 也將移除兩個 WebSocket opt-out 環境變數，仍先嘗試 WebSocket，再視需要回退到 SPDY。

一般實務影響

舊 runtime 若不支援 CRI 回報，新節點可能無法註冊；若 CI 或代理曾依賴 opt-out，互動指令與 port-forward 需要重測。

具體建議

目前先盤點節點映像、CRI 相容性和相關 CI 變數。等正式版與供應商支援公布後，在測試節點驗證註冊、exec 和 port-forward，再安排升級。

驗證與限制

cgroup v1 的移除不是本次直接生效；1.38 預告仍保留短期相容選項。雲端受管 Kubernetes 的可用版本與升級節奏，以各供應商公告為準。

官方來源：Kubernetes · 1.38 官方預告

先驗故障切換 · Data Platform

RDS for SQL Server：符合條件的執行個體可到 500 庫

2026-11-24 · Amazon RDS for SQL Server · 指定組態

原上限 100 提高到最多 500 個資料庫，適用 4 vCPU 以上、非 burstable 的合格 instance class。Single-AZ 涵蓋指定 editions；Multi-AZ 則限定官方列出的 edition 與高可用組態。

一般實務影響

較高密度可減少執行個體數量，但也會讓資源競用、更新中斷及故障影響更多資料庫。500 是上限，不是容量或效能建議值。

具體建議

先以代表性工作負載壓測 CPU、I/O 與連線尖峰，並演練備份還原和故障切換。依復原時間與故障影響分組，再決定整併密度。

驗證與限制

Multi-AZ Standard、使用 Database Mirroring 的 Multi-AZ，以及較小 instance class 仍沿用既有限制。選型時要核對 edition、instance class 和 HA 方式，而非只核對 SQL Server 版本。

官方來源：AWS · RDS SQL Server 上限公告

短訊｜Claude Opus 4.5 將於 2027/01/22 退出 Claude API

Anthropic 在 11/23 宣告 deprecation，預定 2027/01/22 停止 Claude API 上的 Opus 4.5，建議遷往 Opus 5.5。這是 API 退役時程，不代表公告當天已停用，也不等於其他供應平台同日停用。

先盤點模型別名、固定 ID、SDK 設定與排程；挑一批現有案例，比較工具呼叫、結構化輸出、延遲與成本，並給正式切換留緩衝。
