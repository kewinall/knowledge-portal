01
值得試 · Agent / 開發流程

GitHub CLI 等待 PR 事件：省輪詢，不省狀態查核

GitHub 公告：2026-11-18；gh ≥ 2.105.0；Public preview／waitlist

GitHub CLI 新增 gh event listen，讓代理等待 PR review、head、狀態及 check suite 完成事件。Event Streams 使用對外 SSE 連線，不必開公開 webhook 端點；目前限 GitHub.com，須帳號取得預覽存取權。

一般實務影響

適合把反覆查詢 PR 的迴圈改成事件喚醒，但事件不是部署成功或可合併的證明。預覽介面仍可能變動。

具體建議

先在測試 PR 驗證連線、斷線和新 push；每次收到事件後重新核對最新 head、所有必要 checks 與 commit statuses。尚未取得存取權就保留既有查詢流程。

驗證與限制

串流沒有 replay，事件可能重複或亂序；開始監聽及重連後都要補查目前狀態。訂閱 24 小時到期；CLI 可重連與重建訂閱，但離開 listen 不會刪除訂閱。單一 check suite 完成不代表全部檢查完成；Pages 部署仍須獨立查核。

官方來源：GitHub Changelog · CLI 發布GitHub Docs · Event Streams
02
值得試 · AI / 設定治理

AWS AppConfig：模型設定與 Prompt 分開版本化

AWS 公告：2026-11-19；AppConfig 提供服務的 Regions 可用

AWS AppConfig 新增 AI model invocation 與 AI prompt 兩類 configuration profiles。模型識別、推論參數和訊息可集中管理，Prompt 亦可獨立版本化；應用程式可在執行中取得更新，不必每次重部署程式碼。

一般實務影響

模型／Prompt 變更可漸進推出，搭配監測告警回復前版。不代表現有應用會自動接好設定讀取、品質評估及告警。

具體建議

先把一個非正式環境 Prompt 納入版本管理，用固定案例比較正確性、延遲及 token 用量；小流量推出前，實測告警觸發與回復前版流程。

驗證與限制

把模型配置與 Prompt 版本一同寫入測試證據，避免無法重現。AWS 公告稱新 profile 類型無額外費用，不代表模型推論、AppConfig 原有用量或監測服務全部免費。回復配置也不會撤回已完成的外部工具操作，寫入行為仍需既有核准與稽核。

官方來源：AWS What's New · AI configuration profiles
03
需盤點 · Cloud / 可觀測性

EC2 補上效能健康訊號：主機可連線，不代表 GPU 正常

AWS 公告：2026-11-19；GPU 功能限支援的加速運算機型

EC2 新增 performance status checks，可指出影響加速運算效能、但未讓主機失聯的硬體狀況。Detailed Monitoring 同時新增每分鐘 GPU 指標、OpenTelemetry 指標支援，以及 10 秒 CPU utilization 指標。

一般實務影響

可從平台層補足 GPU 使用率與硬體健康觀察，不需在 guest 裡設定；但不能取代程序、容器或應用程式層的監測。

具體建議

先盤點支援的 instance type，對少量主機啟用需要的指標並估算費用；告警先導向人工查核，不要直接把每個 impaired 事件接成無條件重開機。

驗證與限制

Performance status checks 不另收費；Detailed Monitoring 需 opt-in 並按標準 CloudWatch 費率計費。若建議 reboot，先確認工作 checkpoint、停止排入新工作及 drain 計畫，再在維護窗口處理並驗證恢復。這些是建議流程，本文未替任何環境更動設定。
