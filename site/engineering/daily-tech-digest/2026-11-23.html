先做回歸 · Data Engineering

DuckDB 2.0.1 LTS：先測 MERGE 的重複鍵

2026-11-20 · 2.0 LTS 首次修補版

DuckDB 2.0.1 恢復 1.x 的更新行為：如果多筆來源對到同一筆目標，MERGE 與 UPDATE ... FROM 可對每筆匹配執行更新。這與 2.0.0 的行為不同；重複匹配時最終值可能不確定。

一般實務影響

若 ETL 依賴 MERGE 因重複鍵中止，升版後不能再把這個行為當作資料品質防線。RETURNING 在多筆匹配時也可能重複傳回目標列。

具體建議

在 staging 表先驗證業務鍵唯一，測試重複鍵、NULL 及重跑；若需去重，使用明確的排序與平手規則，再比較更新結果與筆數。

驗證與限制

2.0.1 同時收緊 SECRET host／bucket 範圍匹配；核對是否使用完整名稱及顯式連接埠，不再依賴名稱前綴。升級前先用測試憑證驗證預期連線。

官方來源：DuckDB · 2.0.1 LTS 發布說明
02
先檢查觸發 · Agent

OpenHands 1.43.0：完成建立就啟用排程

2026-11-20 · OpenHands v1.43.0 release notes

Automation 設定精靈最後按下建立時，預設與自訂 automation 會以啟用狀態建立。草稿儲存及預先檢查維持停用，不代表建立後還需要手動啟用。

一般實務影響

同一套測試習慣可能在升版後真的觸發排程或 webhook。這是設定精靈建立步驟的變更，不是既有排程一律重新啟用。

具體建議

先用無副作用的任務及隔離測試資源驗證下一次觸發時間。正式建立前先核對時區、觸發條件和工具權限，再檢查首次執行紀錄。

驗證與限制

PR 說明此變更只動最後建立時提交的啟用旗標，未改排程服務的派送方式，也不涵蓋匯入流程。不要把自動啟用等同於所有工具動作已獲核准。

官方來源：OpenHands · 1.43.0OpenHands · 精靈建立行為變更

分層盤點 · Cloud / Security

Dataflow 修補 OpenJDK：先區分 Runner 與映像

2026-11-20 · Google Cloud GCP-2026-082 · CVE-2026-114938

Google 對標準 Java 17／21／25 worker 容器推出服務端緩解，並更新 Apache Beam 2.78.0 中不使用 Portable Runner 的 worker 映像。公告發布時，Portable Runner 與 Flex Template 基底映像更新仍在進行。

一般實務影響

看到服務端緩解或相同 Beam 版本，不等於所有自訂映像都已換成修補後的 JDK。應分別看 Runner、基底映像來源與實際執行版本。

具體建議

先盤點官方、自訂與模板映像。按官方公告更新受影響的 Java runtime，測試一個代表性作業，再核對 worker 版本、吞吐及記憶體。

驗證與限制

Google 列出的非 Portable Runner 修補版為 17.0.21.1+2、21.0.13.1+2、25.0.5.1+2。若升級後出現記憶體異常，先收集 worker 指標，再依公告檢查 GC 相容性。

官方來源：Google Cloud · Dataflow 安全公告
