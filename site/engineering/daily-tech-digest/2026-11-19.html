Agent Framework：兩版 PyPI 套件含惡意程式

GitHub Advisory：2026-11-18；受影響版本：1.26.1、1.26.2

GitHub Advisory 指出，PyPI 的 agent-framework 1.26.1、1.26.2 含有竊取憑證的惡意程式。這兩個版本於 11/17 UTC 上架，後已移除。受影響環境即使未明確 import 套件，也不應排除暴露。

一般實務影響

需要檢查開發、CI runner 和既有容器映像；套件已下架不會移除先前安裝或快取的副本。

具體建議

先比對 lockfile、安裝紀錄、CI 紀錄與映像清單；若曾安裝受影響版本，隔離環境、使用可信來源重建，撤銷或輪替當時可接觸的憑證並查核稽核紀錄。不要只降版。

驗證重點

公告沒有列出 patched version；1.26.0 是未受此次事件影響的舊版，不是新修補版。請在可信環境中檢查建置證據，不要為確認而啟動疑似受污染的 Python 環境。

官方來源：GitHub Advisory · GHSA-764m-3ppc-5m73
02
需檢查 · Kubernetes / 資安

AWS Private CA Connector 修補：升級前先盤點憑證簽發

AWS 公告：2026-11-17 12:00 PST（台北 11/18 04:00）

AWS 修補 AWS Private CA Connector for Kubernetes 的兩項授權問題（CVE-2026-130622、CVE-2026-130623）。受影響的是 aws-privateca-issuer v1.12.0 之前的版本，以及 EKS 加購元件 v1.12.0-eksbuild.1 之前的版本。只使用 cert-manager 但未部署此連接器，不應直接判成受影響。

一般實務影響

這次不能只換映像：新版收緊 namespace 層級 Issuer 的憑證來源，依賴舊行為的簽發或續期可能中斷。

具體建議

先清點各叢集的連接器版本與 Issuer 依賴，照公告先更新 CRD、遷移受影響的 Issuer，再於測試環境驗證簽發及續期，最後分批升級。

驗證重點

如無法立即升級，AWS 建議暫時把相關 Issuer 的建立與更新權限限縮至叢集管理員，並複查現有設定；不要把相容性選項當成完成修補。

官方來源：AWS Security Bulletin · 2026-187-AWS

值得試 · Data Engineering / Cloud

Amazon EMR 8.2 LTS：先驗證增量計算與資料權限

AWS What's New：2026-11-17；EC2 runtime release guide：2026-11-18

Amazon EMR 8.2 LTS 涵蓋 EC2、EKS 和 Serverless，更新至 Spark 4.1.3、Iceberg 1.11.0 與 Delta Lake 4.2.0。AWS 公告列出 Iceberg 物化檢視的增量更新、S3 上 Delta Lake 多叢集並行寫入，以及 Spark 作業與工作階段的使用者身分傳遞。

一般實務影響

適合評估是否能降低重算成本，或讓資料存取依終端使用者授權與稽核。不是所有查詢都會增量更新，也不能把不同部署型態的實際行為視為完全相同。

具體建議

選一條有固定基準的 ETL 作業，在現行和 8.2 分別跑相同樣本；比較增量／全量結果、寫入衝突後的一致性及存取稽核，再決定是否遷移。

驗證重點

對含投影、篩選、inner join 或 SUM／COUNT 的候選物化檢視，可先比較相同資料變更下的結果、重算量和花費。針對既有工作負載另查對應部署型態的 release notes、Spark 相容性與連接器版本。

官方來源：AWS What's New · Amazon EMR 8.2AWS Release Guide · Spark runtime 8.2.0

快訊 · 持續觀察 / AI

MAI Code 2／Flash：Copilot 可用，Foundry 仍有限制

Microsoft AI 公告：2026-11-17；Foundry：僅 Flash 有限存取預覽

Microsoft AI 在 Ignite 發表 MAI Code 2 和 MAI Code 2 Flash。官方公告列為 GitHub Copilot 可用；Microsoft Foundry 目前只公告 Flash 的有限存取預覽，不等於兩款模型已全面提供 API。

一般實務影響

Flash 可作為小型修補或例行修改的候選，但廠商評測與促銷費率不能代替自己的實測。

具體建議

若帳號可選用，先用同一組小修補比較測試通過率、人工返工與延遲；沒有存取權就先觀察，不需遷移既有流程。

驗證重點

把修改範圍、測試失敗時的處置及回報品質納入驗收。先固定模型版本與執行條件，避免把工具差異誤當成模型差異。

官方來源：Microsoft AI · 發布與通路Microsoft AI · Model Card
